# Лаборатория сравнения изображений

**Сравнительное исследование точных, перцептивных, геометрических и векторных подходов к поиску дубликатов изображений.**

[English version](README.md)

`image-similarity-lab` — исследовательский проект на C++20 для реализации, проверки, измерения и сравнения нескольких подходов к обнаружению точных и преобразованных дубликатов изображений.

Это **не демонстрация одного выбранного хэша или одного фиксированного pipeline**. Репозиторий задуман как экспериментальная среда для изучения того, где разные методы работают хорошо, где ошибаются и как их можно объединять в эффективный каскад.

## Проблема

Два файла могут содержать одно и то же изображение, но иметь разные байты из-за повторного JPEG-сжатия, изменения размера, конвертации формата, изменения яркости, crop, rotation, watermark и других преобразований.

Поэтому нужно разделять несколько типов похожести:

- **точные дубликаты** — полностью одинаковые байты файлов;
- **near duplicates** — та же фотография после лёгких преобразований;
- **transformed duplicates** — то же визуальное содержимое после crop, rotation, scale или perspective changes;
- **семантическая похожесть** — разные изображения с близким содержанием.

Проект исследует компромисс между:

- **качеством обнаружения** — precision, recall, false positives и false negatives;
- **устойчивостью** — поведением при контролируемых преобразованиях;
- **производительностью** — временем извлечения признаков, сравнения, throughput и масштабированием;
- **памятью** — размером descriptor на изображение и размером индекса;
- **сложностью системы** — preprocessing, indexing и verification overhead.

## Исследовательский вопрос

> Как объединить exact hashes, perceptual hashes, local feature matching и vector descriptors, чтобы получить хороший компромисс между точностью, задержкой и памятью при поиске near-duplicate изображений?

Долгосрочная цель — исследовать каскадные системы, где дешёвые методы сначала отбирают кандидатов, а более дорогие геометрические или векторные методы подтверждают совпадение.

## Исследуемые подходы

| Семейство | Планируемые методы | Основная цель |
|---|---|---|
| Exact baseline | размер файла, SHA-256 | находить байт-в-байт одинаковые файлы |
| Perceptual hashes | aHash, dHash, pHash, wHash | находить визуальные копии после лёгких преобразований |
| Global descriptors | цветовые и edge histograms | описывать общую структуру изображения |
| Local features | ORB, AKAZE, SIFT baseline | обрабатывать crop, rotation, scale и partial overlap |
| Geometric verification | matching + RANSAC | отбрасывать случайные совпадения локальных признаков |
| Vector descriptors | learned embeddings позже | исследовать сильные copy-detection и semantic baselines |
| Binary indices | brute force, BK-tree, multi-index hashing | ускорять поиск в Hamming space |
| Vector indices | exact search и ANN baselines позже | масштабировать embedding-based retrieval |
| Cascaded systems | дешёвая фильтрация + дорогая проверка | уменьшать среднюю стоимость запроса при сохранении recall |

Ни один метод заранее не считается универсально лучшим. Цель — определить, при каких преобразованиях и условиях каждый подход входит в Pareto frontier по качеству и производительности.

## Экспериментальные данные

Benchmark suite будет содержать исходные изображения, контролируемые положительные преобразования и сложные отрицательные пары.

Планируемые преобразования:

- JPEG recompression;
- resize и format conversion;
- изменения brightness и contrast;
- blur и noise;
- crop и borders;
- rotation и horizontal flip;
- watermarking;
- perspective distortion;
- комбинации нескольких преобразований.

Негативные примеры будут включать визуально похожие, но разные изображения, одинаковые шаблоны с разным содержанием, серийные кадры, похожие сцены и другие hard negatives.

Разбиение на validation и test будет выполняться по исходной фотографии, чтобы её преобразованные версии не попадали в разные splits.

## Метрики

### Качество обнаружения

- TP, FP, FN и TN;
- precision, recall и F1-score;
- false-positive и false-negative rates;
- ROC и precision–recall curves, где это уместно;
- recall@k для indexed retrieval;
- качество отдельно по типу и силе преобразования.

### Производительность

- время декодирования изображения;
- время preprocessing;
- время вычисления hash или descriptor;
- время сравнения одной пары;
- query latency и throughput;
- время построения индекса;
- масштабирование по размеру коллекции.

### Память

- размер descriptor на изображение;
- общий размер индекса;
- стоимость временных аллокаций;
- компромиссы хранения binary и floating-point descriptors.

## Методология

Эксперименты будут раздельно измерять:

- файловый ввод и декодирование;
- нормализацию изображения;
- извлечение признаков;
- поиск кандидатов;
- pair verification;
- расчёт метрик;
- экспорт CSV и построение графиков.

Для каждого отчёта будут фиксироваться компилятор и флаги, модель CPU/GPU, размеры изображений, версия датасета, параметры преобразований, способ выбора thresholds, прогрев, число повторений и статистика измерений.

Thresholds будут подбираться на validation set и один раз проверяться на отдельном test set.

## Текущий статус

**Активная разработка — production C++ foundation и первый binary-similarity baseline.**

Текущая фаза посвящена инфраструктуре проекта, тестам, Hamming distance и первой реализации вычисления хэша по реальному изображению.

Neural embeddings, CUDA, ANN и сложные геометрические методы будут добавлены только после того, как exact и perceptual baselines станут корректными, измеренными и документированными.
